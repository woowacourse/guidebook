# 인사이트 추출 (Extract Insights) — 교차 패턴 탐지 전문가

> 실험 로그 전체를 교차 분석하여 반복되는 패턴을 식별하고,
> 인사이트 문서로 정리한다.

## 인자

$ARGUMENTS — 선택. 특정 카테고리명(예: `레벨1`, `소프트스킬`)을 지정하면 해당 카테고리만 분석. 비어 있으면 전체.

## 절차

### Step 1: 로그 전수 조사

1. `content/logs.ts`에서 대상 로그 목록을 로드한다.
2. 각 로그 MDX를 읽고, 핵심 요소를 추출한다:
   - **교육 설계 원칙** (예: 점진적 스캐폴딩, 거꾸로 학습)
   - **사용된 메커니즘** (예: POE 사이클, KPT 회고, 페어 활동)
   - **관찰된 효과** (예: 심리적 안전감, 메타인지, 전이)
   - **반복 횟수** (몇 기수에 걸쳐 반복했는가)
3. 추출 결과를 구조화된 테이블로 정리한다.

### Step 2: 클러스터링

추출된 요소를 유사도 기준으로 클러스터링한다:

1. **설계 패턴 클러스터**: 같은 교육 설계 원칙을 사용한 로그들
   - 예: "점진적 복잡도" → 코드랩, FE 레벨2 16단계, 비동기 퀴즈
2. **메커니즘 클러스터**: 같은 활동 구조를 사용한 로그들
   - 예: "자기 선언 → 실행 → 회고" → 원정대, 기술 강점 찾기, 한 발짝 스터디
3. **효과 클러스터**: 같은 교육 효과가 관찰된 로그들
   - 예: "심리적 안전감 형성" → 연극 온보딩, 연극 회고, 팀 빌딩

### Step 3: 패턴 정제

각 클러스터에서 인사이트를 정제한다:

1. 3개 이상의 로그가 겹치는 클러스터 → **강한 패턴** (인사이트 문서 작성)
2. 2개 로그가 겹치는 클러스터 → **약한 패턴** (기록만, 추가 실험 대기)
3. 1개 로그만 있는 요소 → **독립 실험** (패턴화 불가, 건너뜀)

### Step 4: 인사이트 문서 작성

강한 패턴마다 `content/education-experiment/insights/{패턴명}.mdx`를 작성한다:

```mdx
# {인사이트 제목}

<Callout>
**핵심 발견**: {한 문장으로 패턴의 핵심}
</Callout>

## 패턴 요약

{2~3문장으로 이 패턴이 무엇이고 왜 중요한지}

## 근거 실험

<CardGrid columns={2}>
  <Card title="{로그1 제목}" href="{로그1 링크}">
    {이 패턴에 기여하는 구체적 요소 1문장}
  </Card>
  ...
</CardGrid>

## 핵심 원칙

1. **{원칙 1}** — {설명}
2. **{원칙 2}** — {설명}
3. **{원칙 3}** — {설명}

## 적용 가이드

| 상황 | 적용 방법 | 주의점 |
|------|-----------|--------|
| ... | ... | ... |

## 관련 교육 모델

- [{관련 원칙}](/education-model/{경로}) — {연결 설명}
```

### Step 5: 메타데이터 업데이트

1. `content/education-experiment/insights/_meta.ts`에 새 인사이트를 등록한다.
2. `content/education-experiment/insights/index.mdx`를 업데이트한다:
   - Placeholder가 남아있으면 제거하고 실제 인사이트 목록으로 교체.
3. 각 인사이트를 커밋한다:
   ```
   extract insight: "{인사이트 제목}" from {N} logs
   ```

### Step 6: 결과 요약

```
## 인사이트 추출 완료

### 강한 패턴 (인사이트 문서 생성)
| 패턴명 | 관련 로그 수 | 카테고리 |
|--------|-------------|----------|

### 약한 패턴 (추가 실험 대기)
| 패턴명 | 관련 로그 수 | 필요한 추가 실험 |
|--------|-------------|-----------------|

### 독립 실험 (패턴화 불가)
| 로그 | 이유 |
|------|------|
```

## 제약

- 인사이트는 **로그에 실제로 기록된 내용**에서만 추출한다. 추측하지 않는다.
- 기존에 작성된 인사이트(hidden 포함)가 있으면 덮어쓰지 않고, 내용을 보강한다.
- 약한 패턴을 강한 패턴으로 승격시키지 않는다. 추가 실험 데이터를 기다린다.
- 패턴 이름은 교육학 용어보다 **이 프로젝트에서 사용하는 언어**를 우선한다.
