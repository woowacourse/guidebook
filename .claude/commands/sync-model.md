# 교육 모델 동기화 (Sync Model) — 실험 → 이론 반영

> 승격 판정을 받은 인사이트와 패턴을 교육 모델 문서에 반영한다.
> 기존 교육 모델을 수정하지 않고, 실험에서 검증된 사례를 **추가**하는 방식으로 동기화한다.

## 인자

$ARGUMENTS — 선택.
- 특정 인사이트 파일명 (예: `scaffolding-pattern`) → 해당 인사이트만 반영
- `scan` → 반영 대상만 식별하고 실행하지 않음
- 비어 있으면 전체 인사이트를 스캔하여 미반영 항목을 반영

## 절차

### Step 1: 반영 대상 식별

1. `content/education-experiment/insights/` 디렉토리의 모든 인사이트 MDX를 읽는다.
2. `content/education-model/` 디렉토리 구조를 파악한다.
3. 각 인사이트의 "관련 교육 모델" 섹션을 확인한다.
4. 아직 교육 모델에 반영되지 않은 인사이트를 식별한다:
   - 인사이트 문서에 교육 모델 링크가 있으나, 교육 모델 문서에 역참조가 없는 경우
   - 인사이트 문서에 "관련 교육 모델" 섹션 자체가 없는 경우

### Step 2: 매핑

각 미반영 인사이트를 교육 모델 섹션에 매핑한다:

| 인사이트 유형 | 반영 대상 | 반영 방식 |
|--------------|-----------|-----------|
| 교육 설계 패턴 | `design-patterns/catalog.mdx` | 새 패턴 항목 추가 |
| 교육 원칙 검증 | `philosophy/core-principles.mdx` | 실증 사례 추가 |
| 커리큘럼 시사점 | `curriculum/` 해당 문서 | 설계 근거 보강 |
| 평가 관련 | `assessment/` 해당 문서 | 평가 방법론 사례 추가 |
| 운영 관련 | `operations/` 해당 문서 | 운영 가이드 보강 |
| 실패 패턴 | `failed-experiments/catalog.mdx` | 실패 사례 추가 |

### Step 3: 반영 실행

**반영 원칙:**

1. **추가만 한다** — 기존 문장/문단을 삭제하거나 재작성하지 않는다.
2. **근거를 명시한다** — 반영하는 내용에 원본 로그/인사이트 링크를 반드시 포함한다.
3. **한 커밋에 하나** — 각 반영을 개별 커밋한다.
4. **한 사이클 최대 3건** — 한 번에 너무 많이 반영하면 교육 모델의 일관성이 깨진다.

**반영 패턴:**

#### 디자인 패턴 추가 (catalog.mdx)

```mdx
### {패턴명}

**문제**: {이 패턴이 해결하는 교육 문제}
**해결**: {패턴의 핵심 메커니즘}
**적용 사례**: [{실험 로그1 제목}]({링크}), [{실험 로그2 제목}]({링크})
**효과**: {관찰된 교육 효과 요약}
```

#### 기존 섹션에 사례 추가

```mdx
> **실험 근거**: [{인사이트 제목}](/education-experiment/insights/{slug})에서
> {N}개 로그의 교차 분석으로 확인된 패턴. 상세 실험 기록은
> [{로그 제목}](/education-experiment/logs/{slug}) 참조.
```

### Step 4: 역참조 추가

반영 후, 인사이트 문서의 "관련 교육 모델" 섹션을 업데이트한다:

```mdx
## 관련 교육 모델

- [디자인 패턴 카탈로그](/education-model/design-patterns/catalog#{패턴앵커}) — ✅ 반영 완료 (2026-04-01)
```

### Step 5: 메타데이터 업데이트

1. `content/updates.ts`에 반영 내용을 추가한다:
   ```ts
   {
     date: '2025년 8기',
     title: '{반영 제목}',
     description: '실험 로그에서 검증된 {패턴/원칙}을 교육 모델에 반영.',
     href: '/education-model/{경로}',
     status: 'active',
   }
   ```
2. 교육 모델 `_meta.ts`에서 hidden 항목이 활성화 대상이면 `display: 'hidden'`을 제거한다.

### Step 6: 커밋 및 요약

각 반영마다:
```
sync model: "{인사이트 제목}" → education-model/{섹션}
```

최종 요약:
```
## 교육 모델 동기화 완료

| 인사이트 | 반영 대상 | 반영 방식 |
|----------|-----------|-----------|
| {인사이트1} | {섹션} | {추가/보강} |

### 미반영 항목 (다음 사이클)
| 인사이트 | 이유 |
|----------|------|
| {인사이트N} | {한 사이클 최대 3건 초과 / 추가 검증 필요} |
```

## 제약

- 교육 모델의 **기존 내용을 수정하거나 삭제하지 않는다**.
- 승격 루브릭(`.claude/promotion-rubric.md`)을 수정하지 않는다.
- 인사이트에 근거가 없는 내용을 교육 모델에 추가하지 않는다.
- 한 사이클에 교육 모델 반영은 **최대 3건**으로 제한한다.
- `scan` 모드에서는 식별만 하고 변경하지 않는다.
