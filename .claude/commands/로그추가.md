# 새 실험 로그 추가

> 팀원이 새 실험 로그를 쓸 때 첫 번째로 치는 커맨드. 원본 자료만 넘기면 슬러그·제목·요약·MDX 본문·`logs.ts`·`updates.ts`·브랜치·PR을 한 번에 만든다.

## 진행 안내 (체크리스트)

커맨드를 받자마자, 그리고 **단계가 바뀔 때마다** 전체 5단계 체크리스트를 다시 출력합니다. 사용자가 항상 "지금 어디 / 남은 단계 무엇"을 한눈에 볼 수 있도록.

상태 마커:

- `[ ]` 아직 안 함
- `[ ] ← 진행 중` 지금 이 단계
- `[x]` 완료

커맨드 직후 첫 출력:

```
실험 로그 추가는 5단계로 진행합니다.

[ ] 1. 콘텐츠 설명 · 원본 자료 받기      ← 진행 중
[ ] 2. 정리 방식 선택 (분석 / 요약 / 종합)
[ ] 3. 메타데이터 자동 추천 확인
[ ] 4. 브랜치 생성 · 파일 작성
[ ] 5. 커밋 · 푸시 · PR 등록 (@wmakerjun 멘션)
```

Step 2 진입 시:

```
[x] 1. 콘텐츠 설명 · 원본 자료 받기
[ ] 2. 정리 방식 선택 (분석 / 요약 / 종합)   ← 진행 중
[ ] 3. 메타데이터 자동 추천 확인
[ ] 4. 브랜치 생성 · 파일 작성
[ ] 5. 커밋 · 푸시 · PR 등록 (@wmakerjun 멘션)
```

이런 식으로 단계가 끝날 때마다 체크박스를 갱신해 다시 보여줍니다. 마지막 단계 완료 후 결과 보고 직전에는 5개 모두 `[x]`로 출력합니다.

---

## Step 1: 콘텐츠 설명과 원본 자료 받기

다음 문구로 시작합니다.

> **추가하려는 콘텐츠에 대한 1줄 설명과 원본 자료를 링크, 파일, 텍스트 원문 등으로 자유롭게 입력해주세요.**
>
> 1줄 설명 예시:
> - 페어 프로그래밍 회고 5회 누적 패턴
> - 안드로이드 레벨2 강의형 → 참여형 전환 실험
> - 레벨3 데모데이 회고 시리즈
>
> 원본 자료 예시:
> - 슬랙 스레드 / 디스코드 로그 복붙
> - 노션·구글 독스·깃허브 토론 링크
> - 개인 메모, 회고 노트, 슬라이드 파일
> - 발표 녹취록·이메일 본문 같은 텍스트 원문
>
> 의도와 자료만 주시면, 슬러그·제목·요약·본문·메타데이터·PR까지 제가 알아서 정리합니다.

답변에서 **1줄 설명**과 **원본 자료**(본문/링크/첨부)를 확보합니다. 하나라도 비면 한 번만 가볍게 보충 요청하고, "원본 없이 진행" 응답이면 그대로 갑니다.

---

## Step 2: 정리 방식 선택

`AskUserQuestion` (multiSelect: false)로 묻습니다.

- **종합** *(권장)* — 요약 + 잘 작동한 것 / 개선 / 다음 실험
- **요약** — 핵심 사실과 흐름만 압축
- **분석** — 패턴·인과·맥락까지 깊게 해석

자유 텍스트 응답("그냥 요약만" 등)은 위 셋 중 하나로 매핑합니다.

---

## Step 3: 메타데이터 자동 추천 + 확인

원본·의도·정리 방식을 바탕으로 LLM이 모든 메타데이터를 추론하고 표로 한 번에 확인을 받습니다.

| 필드 | 추론 규칙 |
| --- | --- |
| 슬러그 | 영문 소문자 + 하이픈. 원본 핵심 키워드 2~4개 조합. `content/education/logs/{슬러그}.mdx` 충돌 시 `-2`, `-3` 자동 부여 |
| 제목 | 한국어. 원본 명사구 우선. 추상적이지 않게 |
| 한 줄 요약 | 한 문장. "무엇을 / 누구를 대상으로 / 어떤 결과였는지" |
| phases | `온보딩` ~ `레벨5` 중 명시·강한 시사가 있을 때만. 약하면 `[]` |
| 분류 | 아래 5개 중 **하나**를 LLM이 원본 내용으로 판단해 선택 |

**분류 5종과 저장 매핑:**

| 분류 (표시) | 판단 기준 | logs.ts 저장 |
| --- | --- | --- |
| 웹 백엔드 | Spring/Java/Kotlin 백엔드/DB 등 BE 기술 위주 | `tracks: ['웹 백엔드']` |
| 웹 프론트엔드 | React/TypeScript/CSS/렌더링 등 FE 기술 위주 | `tracks: ['웹 프론트엔드']` |
| 모바일 안드로이드 | Compose/Activity/Kotlin Android 등 | `tracks: ['모바일']` |
| 소프트스킬 | 회고·신뢰·정체성·협업·팀빌딩·UX 등 트랙 무관 | `tracks: []`, `themes: ['소프트스킬']` |
| 공통 | 이력서·온보딩·연극·자기소개·전 트랙 학습 활동 | `tracks: [...ALL_TRACKS]` |

> `코치훈련` 카테고리는 이 흐름에서 자동 추론하지 않습니다. 필요하면 PR 머지 후 `content/logs.ts`에서 `themes: ['코치훈련']`을 수동으로 추가하세요.

추천 결과 출력 예시:

```
[3/5] 메타데이터 자동 추천 확인

| 필드        | 추천 값                              |
| ----------- | ------------------------------------ |
| 슬러그      | pair-programming-retro               |
| 제목        | 페어 프로그래밍 회고 5회 누적 패턴   |
| 한 줄 요약  | 레벨1 페어 회고 5회를 거쳐 굳어진 ... |
| phases      | [레벨1]                              |
| 분류        | 소프트스킬                           |

이대로 진행할까요? (Y / 수정)
```

`수정`이면 어떤 필드를 어떻게 바꿀지 자유 텍스트로 받고 표를 다시 출력해 재확인합니다.

## Step 4: 브랜치 생성 · 파일 작성

### 4-1. 브랜치 생성

```bash
git checkout -b log/{슬러그}
```

같은 이름 브랜치가 있으면 `log/{슬러그}-2` 식으로 자동 회피.

### 4-2. MDX 스켈레톤 생성

`content/education/logs/{슬러그}.mdx`를 Write 도구로 생성합니다. **Step 2의 정리 방식**에 따라 본문 구조가 달라집니다.

**공통 헤더 (모든 모드):**

```mdx
---
title: {제목}
description: {한 줄 요약}
---

import { Callout } from 'nextra/components'

# {제목}

<Callout>
**대상**: (추론된 트랙·단계로 자동 채움)
**맥락**: (사용자 의도 1~2줄을 그대로 사용)
**핵심 질문**: (원본에서 추론. 없으면 비워둠)
</Callout>
```

**종합 모드 본문 (기본):**

```mdx
## 맥락

(왜 이 실험이 필요했는지)

## 시도한 것

(타임라인·팀 구성·템플릿 등)

## 관찰

(수치·인용 중심의 사실)

## 반성

**잘 작동한 것**
- (구체적 근거)

**개선이 필요한 것**
- (구체적 근거)

## 다음 실험

(연속선상의 다음 단계)

## 원본 자료

(첨부 링크 또는 인용 원문)
```

**요약 모드 본문:**

```mdx
## 핵심 요약

(원본의 사실과 흐름을 5~10줄로 압축)

## 원본 자료

(첨부 링크 또는 인용 원문)
```

**분석 모드 본문:**

```mdx
## 맥락

(배경)

## 시도한 것

(운영 방식)

## 관찰

(수치·인용 중심의 사실)

## 해석

(왜 그렇게 되었는지. 인과·패턴·맥락)

## 다음 실험

(연속선상의 다음 단계)

## 원본 자료

(첨부 링크 또는 인용 원문)
```

본문은 원본을 토대로 LLM이 직접 채웁니다. 빈 섹션은 `(원본에 명시 없음)`을 명시합니다.

### 4-3. `content/logs.ts` 갱신

Edit 도구로 `const logs: Log[] = [` 다음 줄에 새 항목 삽입(배열 맨 위). Step 3에서 선택한 **분류**에 따라 `tracks`/`themes` 필드를 다음과 같이 채웁니다.

| 분류 | 삽입 필드 |
| --- | --- |
| 웹 백엔드 | `tracks: ['웹 백엔드']` |
| 웹 프론트엔드 | `tracks: ['웹 프론트엔드']` |
| 모바일 안드로이드 | `tracks: ['모바일']` |
| 소프트스킬 | `tracks: []`, `themes: ['소프트스킬']` |
| 공통 | `tracks: [...ALL_TRACKS]` |

기본 삽입 형태:

```ts
  {
    slug: '{슬러그}',
    title: '{제목}',
    description: '{한 줄 요약}',
    href: '/education/logs/{슬러그}',
    date: '{date +%Y-%m-%d}',
    phases: [{추론된 phases}],
    tracks: [{분류에 따른 tracks 값}],
{소프트스킬 분류면: `    themes: ['소프트스킬'],`}
  },
```

### 4-4. `content/updates.ts` 갱신

랜딩 타임라인에 자동 노출합니다 (옵션 없음). `const updates: Update[] = [` 다음 줄에 삽입:

```ts
  {
    date: '{updates.ts 첫 항목의 date 라벨 그대로}',
    title: '{제목}',
    description: '{한 줄 요약}',
    href: '/education/logs/{슬러그}',
    status: 'active',
  },
```

`date` 라벨은 기존 최상단 값을 그대로 재사용합니다.

### 4-5. `llm-wiki/raw/` 동기화 + `llm-wiki/log.md` ingest 기록

LLM Wiki(Karpathy 패턴) 의 raw layer 에 같은 콘텐츠를 평문 마크다운으로 dual-write 합니다. 발행본(`content/`) 과 LLM 작업 공간(`llm-wiki/`) 의 단방향 동기화를 유지하기 위함.

**4-5-1. `scripts/mdx-to-raw.mjs` 호출로 평문 변환:**

`Bash` 도구로 변환 스크립트를 직접 호출합니다. **LLM 이 직접 변환하지 마세요** — 스크립트가 검증된 규칙으로 일관 처리합니다.

```bash
node scripts/mdx-to-raw.mjs \
  --input content/education/logs/{슬러그}.mdx \
  --output llm-wiki/raw/{date}-{슬러그}.md \
  --captured {date} \
  --source-type log
```

스크립트가 자동 처리하는 변환 규칙:
- MDX frontmatter (`---title:..description:..---`) 제거
- `import { ... } from '...'` 라인 제거
- `<Callout>...</Callout>` → blockquote (`>` 접두)
- `<Mermaid chart={`...`}/>` → ` ```mermaid ``` ` 코드 블록
- `{/* MDX 주석 */}` 제거 (다중 라인)
- `<Card>`, `<Hero>`, `<Toggle>`, `<Timeline>`, `<TimelineItem>`, `<Placeholder>` 등 JSX 컴포넌트 제거 (내용은 유지)
- `published_at` frontmatter 자동 삽입 (원본 mdx 추적)

스크립트가 실패하면 (예: 입력 파일 없음) Bash 명령이 non-zero 종료 — 사용자에게 보고하고 작업 중단.

**4-5-2. `llm-wiki/log.md` ingest 한 줄 기록:**

Edit 도구로 `llm-wiki/log.md` 맨 위 (이전 가장 최신 항목 바로 위) 에 추가:

```markdown
## [{YYYY-MM-DD}] ingest | raw/{date}-{슬러그}.md

`/로그추가` 자동 dual-write — 발행본 `content/education/logs/{슬러그}.mdx` 와 동일 내용을 raw 로 동기화.
```

**중요**: protect-raw 훅이 활성화된 상태에서 신규 `llm-wiki/raw/{date}-{슬러그}.md` Write 는 허용됩니다(새 파일). 기존 raw 수정만 차단됨.

## Step 5: 커밋 · 푸시 · PR 등록

### 5-1. 커밋

```bash
git add content/education/logs/{슬러그}.mdx content/logs.ts content/updates.ts llm-wiki/raw/{date}-{슬러그}.md llm-wiki/log.md
git commit -m "$(cat <<'EOF'
add experiment log: {제목}

{한 줄 요약}

발행본: content/education/logs/{슬러그}.mdx
LLM Wiki raw: llm-wiki/raw/{date}-{슬러그}.md (dual-write)

Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
EOF
)"
```

### 5-2. 푸시

```bash
git push -u origin log/{슬러그}
```

### 5-3. PR 생성

**PR 본문은 절대 템플릿을 그대로 붙여 넣지 않습니다.** Step 4에서 직접 작성한 MDX 본문과 Step 3에서 확정한 메타데이터를 기반으로 아래 구조에 맞춰 실제 내용을 채워 넣어야 합니다. 빈 섹션이나 placeholder가 남아 있으면 안 됩니다.

**본문 발췌 규칙 (정리 방식별):**

| 정리 방식 | 발췌 대상 섹션 | 표현 방식 |
| --- | --- | --- |
| 종합 | 맥락 / 시도한 것 / 관찰 / 반성(잘 작동한 것·개선) / 다음 실험 | 각 섹션에서 핵심 1~2문장씩 bullet으로 압축 |
| 요약 | 핵심 요약 | 본문 3~6줄을 그대로 인용하거나 1~2문장으로 더 압축 |
| 분석 | 맥락 / 시도한 것 / 관찰 / 해석 / 다음 실험 | 각 섹션에서 핵심 1~2문장씩 bullet으로 압축. **해석은 반드시 포함** |

- 본문에 `(원본에 명시 없음)`이 적힌 섹션은 PR에서 생략합니다(억지로 채우지 않음).
- 인용·수치·고유명사가 있으면 우선 보존합니다.
- 한 섹션당 최대 3~4줄을 넘기지 않습니다. PR 본문은 머지 리뷰어가 30초 안에 훑을 수 있어야 합니다.

**PR 본문 템플릿:**

```bash
gh pr create --title "add: {제목}" --body "$(cat <<'EOF'
## 요약
- {한 줄 요약}
- 원본 자료를 바탕으로 {분석 / 요약 / 종합} 방식으로 정리한 실험 로그입니다.

## 메타데이터
| 필드 | 값 |
| --- | --- |
| 슬러그 | `{슬러그}` |
| phases | {phases 또는 '미지정'} |
| 분류 | {Step 3에서 선택한 분류 표시값} |
| tracks | {logs.ts에 들어간 tracks 값} |
| themes | {themes 값 또는 '-'} |
| date | {YYYY-MM-DD} |

## 본문 핵심
{정리 방식별 발췌 규칙에 따라 LLM이 직접 채움.
 종합/분석 모드:
   ### 맥락
   - ...
   ### 시도한 것
   - ...
   ### 관찰
   - ...
   ### 반성 또는 해석
   - ...
   ### 다음 실험
   - ...
 요약 모드:
   {핵심 요약 본문 인용 또는 압축}
}

## 원본 자료
- {원본 링크/파일/출처를 bullet으로 나열. 비공개 자료면 '내부 메모(비공개)' 표기}

- `content/updates.ts` (랜딩 타임라인에 자동 노출)
```
