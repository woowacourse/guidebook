# /문장점검

발행 본문(`content/**`)과 컴포넌트 텍스트(`components/**`)에서 **AI 글쓰기 흔적이 나는 문장부호**를 검출한다. 현재 규칙은 **em-dash(`—`)** 하나다.

> 왜: 문장·절 사이에 `—`를 끼워 부연하는 건 대표적인 'AI가 쓴 티'다(예: "…아닌 <strong>—</strong> 함께 자란 동료"). 이 저장소 본문은 `—`를 쓰지 않고 **쉼표·마침표·괄호**로 푼다. 자매 커맨드 `/말투점검`(합니다체)과 짝을 이룬다.

## 실행

```bash
npm run lint:style
# 또는
node scripts/style/ai-style-lint.mjs
```

## 동작

`scripts/style/ai-style-lint.mjs` 가 수행한다:

1. `content/**/*.{mdx,ts}` 와 `components/**/*.tsx` 를 스캔한다.
2. 검사 대상에서 **제외**: 코드블록(```)·인라인 코드(`)·frontmatter·블록쿼트(`>` 인용)·코드 주석(`//`, `/* */`, JSDoc `*`).
3. 남은 **본문·문자열·JSX 텍스트**에서 `—` 를 검출해 `file:line` 으로 보고한다.
4. 1건이라도 있으면 종료코드 1(= 실패).

## 위반 처리

- **본문(저자 글):** `—` 를 문맥에 맞게 고친다.
  - 문장 속 부연이면 → 쉼표/괄호로 풀거나, 문장을 둘로 나눈다. (예: `아닌 — 함께` → `아닌 함께`)
  - "라벨 — 설명" 형식이면 → 쉼표·콜론(`:`)·줄바꿈으로 바꾸거나 그대로 둘지 **사람이 판단**한다.
- **예외(고치지 않음):** 따옴표·블록쿼트 안 **실제 발화 인용**(크루·코치 말)의 `—` 는 verbatim이므로 보존한다. 스크립트가 블록쿼트는 자동 제외하지만, 인라인 인용은 사람이 확인한다.

## 인자

- (없음) — 전체 범위 점검 후 리포트 출력.

## 확장

- 새 AI-흔적 규칙(예: 특정 상투구·이모지·과잉 헤지)을 추가하려면 `scripts/style/ai-style-lint.mjs` 상단의 `RULES` 배열에 한 줄 더한다(사람이 유지보수).
- 검사 범위는 같은 스크립트의 `ROOTS` 로 조정한다.

## 참고
