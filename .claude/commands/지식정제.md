# 지식 정제 (compile)

> 누적된 `llm-wiki/raw/` 를 읽고 → `llm-wiki/wiki/` 의 백과 노트를 합성·갱신. `index.md`·`log.md` 동시 동기화. 카파시 정통 워크플로의 "compile" 단계.

> **반드시 `knowledge-wiki` 스킬을 먼저 로드한다.** 모든 규약·금지 사항은 거기 있다.

## 인자

| 인자 | 동작 |
|---|---|
| (없음) | 마지막 정제 이후 새로 들어온 raw 전부 (대화형 — Step 4 사용자 승인 거침) |
| `자동` | **비대화형 자동 모드**: `compile-state.mjs pending` (wiki sources 에 없는 루트 raw) 중 `compileConfig.batchSize` (기본 5) 만큼 처리. wiki-compiler 의 자기 검증을 통과한 draft 만 자동 반영. 처리분은 반드시 어떤 노트의 `sources:` 에 등재(수렴 보장). |
| `전부` | llm-wiki/raw/ 안 모든 파일 (재합성 — 신중하게) |
| `raw/<경로>` | 특정 raw 1개만 |
| `--미리보기` | wiki/ 갱신 없이 어떤 노트가 영향받을지 보고만 |

## 진입 시 첫 출력 (체크리스트)

```
지식 정제는 5단계로 진행합니다.

[ ] 1. 대상 raw 식별                                ← 진행 중
[ ] 2. 기존 wiki·index 컨텍스트 로드
[ ] 3. wiki-compiler 에이전트에 위임 → 노트 draft
[ ] 4. 사용자 확인 (draft 검토)
[ ] 5. wiki/ 반영 + index.md·log.md 갱신
```

## Step 1: 대상 raw 식별

- `log.md` 의 가장 최근 `## [YYYY-MM-DD] ingest` 이후 추가된 raw 파일을 식별.
- 또는 인자로 명시된 특정 파일.
- 대상이 0개면 "정제할 새 raw가 없습니다. /지식흡수 먼저 실행하세요." 출력 후 종료.
- 대상이 10개 초과면 사용자에게 묻는다: "한 번에 N개는 많습니다. 5~7개씩 나눌까요?" (카파시 권고 "start with ten sources")

## Step 2: 기존 컨텍스트 로드

`wiki-compiler` 에이전트에 넘기기 전 메인이 먼저 읽는다:
- `llm-wiki/index.md` 전체 (단일 컨텍스트에 들어가는 크기)
- `llm-wiki/AGENTS.md` 의 wiki 규약·frontmatter 필수 필드
- `llm-wiki/log.md` 최근 5개 항목

이 셋이 에이전트의 입력 컨텍스트가 된다.

## Step 3: wiki-compiler 에이전트에 위임

`Agent` 도구로 `wiki-compiler` 에이전트 호출. 다음을 명확히 전달:

```
입력:
- 정제 대상 raw 파일 N개 경로
- 현재 index.md 내용 (라우팅 결정용)
- 영향받을 가능성 있는 기존 wiki 노트 슬러그 후보 (필요 시 미리 grep)

지시:
1. 각 raw를 읽고, 어떤 wiki 노트(신규/갱신)에 매핑할지 결정.
2. 한 raw가 여러 노트에 분산될 수 있음 (한 노트 = 한 아이디어 원칙).
3. 자기 언어로 재작성. 복붙 금지.
4. frontmatter 필수 필드 채움 (title·tags·sources·links·updated).
5. 결과를 draft 형태로 반환 (실제 wiki/ 에 쓰지는 말 것 — 메인이 사용자 확인 후 반영).
```

에이전트는 별도 컨텍스트에서 실행되므로 본 메인 컨텍스트가 가벼워진다.

## Step 4: 사용자 확인 (draft 검토)

에이전트가 반환한 draft 목록을 사용자에게 보고:

```
정제 결과 draft:

신규 노트 (3):
- wiki/feedback-loop.md         (sources: raw/2026-06-09-pair-coach-pr-fear.md + 2개)
- wiki/psychological-safety.md  (sources: raw/2026-06-09-pair-coach-pr-fear.md + 1개)
- wiki/code-review-as-teaching.md (sources: raw/...)

갱신 노트 (1):
- wiki/pair-coding-rotation.md  (links 에 feedback-loop 추가)

index.md 추가 라인:
- 핵심 개념 그룹에 2개 추가
- 디자인 패턴 그룹에 1개 추가

반영할까요? (y / 수정 요청)
```

사용자가 거부하거나 수정 요청하면 다시 에이전트 호출.

## Step 5: 반영

승인되면:
1. `Write` 또는 `Edit` 로 wiki/ 파일들 갱신.
2. `index.md` 에 새 라인 추가 (해당 그룹 아래, 알파벳 순).
3. `log.md` 맨 위에 한 줄 추가:
   ```markdown
   ## [YYYY-MM-DD] compile | raw N개 → wiki M개
   신규: feedback-loop, psychological-safety, code-review-as-teaching
   갱신: pair-coding-rotation
   ```
4. 결과 요약 출력 (변경된 파일 목록 + 다음 권장).

## 절대 금지

- ❌ raw 파일 수정 (불변 원칙)
- ❌ 자기 확신 없이 wiki 노트 생성 (출처 모호하면 보류)
- ❌ 복붙 (반드시 자기 언어로 재작성)
- ❌ index.md 한 줄을 단락으로 늘림
- ❌ wiki 안 하위 폴더 생성

## 빈도 권장

- 사용자 호출 주기: 주 1회 또는 raw 5~10개 누적 시
- 한 번에 처리 권장량: 5~7개 raw → 3~5개 wiki 노트
- 너무 잦으면 wiki가 흩어지고, 너무 드물면 raw가 잊혀짐

## `자동` 모드 상세

`/지식정제 자동` 호출 시 동작:

1. `compileConfig.batchSize` (sync-state.json, 기본 5) 읽기.
2. **미합성 raw 목록 추출**: `node scripts/llm-wiki/compile-state.mjs pending`.
   - "미합성" = 어떤 wiki 노트의 `sources:` 에도 적히지 않은 `llm-wiki/raw/` **루트** `*.md`.
   - wiki sources 에서 매번 동적 계산하므로 별도 마커/ledger 동기화가 필요 없다 (stale 불가능).
   - 하위 폴더(`external/`·`derived/`·`conversations/`)는 deliberate-only 라 자동 대상에서 제외 — 인자로 명시할 때만 처리 (`/지식정제 raw/external/...`).
3. 0개면 "정제할 새 raw 가 없습니다" 후 종료.
4. batchSize 초과 시 **오래된 순으로 batchSize 만큼만** 처리 (캡 = `maxBatchSize`).
5. wiki-compiler 위임 → draft 반환.
6. 에이전트의 자기 검증 5단계를 통과한 draft 만 반영. 보류·충돌 항목은 log.md 에 기록 후 다음 사이클로.
7. wiki/·index.md 갱신. **처리한 raw 는 반드시 어떤 wiki 노트의 `sources:` 에 등재한다** — 신규 노트 없이 "이미 흡수됨" 으로 판정한 raw 도 가장 관련 깊은 기존 노트의 `sources:` 에 추가해야 다음 사이클에서 미합성으로 재검출되지 않는다 (수렴 보장).
8. `lastCompileDate` 을 오늘로 갱신 (선택·정보용). **`lastCompileCommit` advance 는 더 이상 탐지에 쓰이지 않는다** — 탐지는 wiki sources 동적 계산이 담당. (legacy 필드로 남겨두되 의존 금지.)
9. log.md 에 `## [YYYY-MM-DD] compile (자동) | raw N개 → wiki M개` 한 줄 추가.

**안전장치:**
- 사용자 승인 없이 wiki 변경 — 대신 wiki-compiler 의 자기 검증과 batchSize 캡이 안전망.
- 탐지 범위는 루트 raw 만 (하위 폴더 제외). 하위 폴더는 deliberate 모드로만.
- 한 사이클 처리량이 maxBatchSize 초과면 강제 컷 + log.md 에 "다음 사이클로 N개 남음" 명시.
- 자기 검증 실패한 draft 가 batchSize 의 절반 초과면 자동 모드 중단 → 사용자에게 보고.
- **동시성**: 실행 전 `git status` 로 다른 세션의 동시 컴파일 흔적을 점검한다 (race·중복 방지).

**자동 모드를 쓰지 말아야 할 때:**
- 사이클이 마지막으로 돈 게 3개월 이상 전 → wiki 갱신 양이 너무 커서 사람 검토 필요. `/지식정제` (대화형) 권장.
- raw 파일이 평소와 다른 종류 (예: 첫 외국어 raw) → 사람 확인 필요.

## 예시

```
사용자: /지식정제

LLM:    [Step 1] log.md 보니 마지막 ingest 이후 raw 6개 누적됐습니다.
        [Step 2] index.md 로드 (현재 0 articles)
        [Step 3] wiki-compiler 호출 중...

[에이전트 작업 후]

LLM:    [Step 4 draft]
        신규 노트 3개:
        - wiki/feedback-loop.md     (피드백 루프 길이가 학습 속도를 결정)
        - wiki/psychological-safety.md
        - wiki/pr-fear-pattern.md   (stub — 더 많은 raw 필요)

        반영할까요?

사용자: y

LLM:    [Step 5]
        ✓ 3개 wiki 노트 생성
        ✓ index.md 갱신 (핵심 개념 3개 추가)
        ✓ log.md compile 한 줄 기록
        다음: /지식점검 으로 정합성 검사 가능
```
