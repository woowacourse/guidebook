# /채점신뢰도 — 채점 신뢰도(재현성) 측정

> `/로그평가`가 로그를 **1번** 채점한다면, `/채점신뢰도`는 같은 로그를 **N번 독립 채점**해
> 점수가 얼마나 재현되는지(측정 변동성 = σ)를 잰다. autoresearch의 측정 인프라를 신뢰도 차원으로 확장한 것.
>
> **측정하는 것:** 신뢰도(reliability) — 반복 채점의 일관성. σ로 수치화된다.
> **측정 못 하는 것:** 타당도(validity) — 점수가 사람 판단과 맞는지. 이건 사람 골드 로그 보정으로만 잡는다.

## 인자

`$ARGUMENTS` — `<로그 파일명> [N]`
- 로그 파일명 (예: `expedition`). 필수.
- N — 채점 반복 횟수. 생략 시 **10**. (2026-06-23 파일럿에서 측정한 채점기 σ≈0.8 기준, 대부분 로그는 이 정도면 합격선 판정이 안정적이다. 경계에 바짝 붙은 로그만 더 늘린다. σ가 더 큰 로그가 쌓이면 이 기본값을 재검토한다.)
- 예: `/채점신뢰도 expedition` · `/채점신뢰도 expedition 20`

## 절차

1. `.claude/log-quality-rubric.md`를 읽어 평가 기준을 로드한다. (총점 25점, 등급 임계값 21/16/11/6)
2. 대상 로그 `content/education/logs/{로그}.mdx`를 읽는다.
3. **N개의 독립 채점 서브에이전트를 병렬로 띄운다.** 각 에이전트는:
   - 같은 로그를 루브릭 D1~D5로 엄격히 채점한다.
   - **차원 평가 순서를 매번 무작위로 섞는다** (순서·앵커링 효과를 분산에 포함시켜, 판정을 실제로 뒤집는 "의사결정 변동성"을 잰다 — 동일 조건 반복이 만드는 가짜로 작은 σ를 피한다).
   - 점수 벡터만 JSON으로 반환한다: `{"D1":n,"D2":n,"D3":n,"D4":n,"D5":n}`. 설명·산문 없이 숫자만.
   - 독립 에이전트 호출 자체가 독립 표본을 만든다.
4. N개 점수 벡터를 모아 스크래치패드에 JSON으로 쓴다:
   ```json
   { "log": "{로그}", "rubric": "quality", "boundaries": [21,16,11,6], "scores": [ ... ] }
   ```
5. 집계기를 실행한다 — 산수는 LLM이 아니라 결정론적 스크립트가 한다:
   ```bash
   node scripts/score-variance/aggregate.mjs <스크래치패드JSON> --date=<오늘> --append=.research/judge-variance.tsv
   ```
6. 스크립트가 출력한 보고서(차원별 σ, 총점 평균±σ, 95% 신뢰구간, 합격선 판정, 권장 n)를 그대로 보여주고, 한 문단으로 해석을 덧붙인다.

## 출력 해석 가이드

- **신뢰구간이 임계값을 안 넘으면** → 이 N으로 판정 신뢰 가능.
- **걸치면** → 스크립트가 제안한 횟수만큼 추가 채점. 그래도 걸치면 **사람 검토**로 넘긴다(샘플 부족이 아니라 진짜 경계선 로그).
- σ가 비정상적으로 크면(예: 총점 σ>3) → 로그가 모호하거나 루브릭 해석이 갈리는 신호. 채점을 늘리기 전에 로그/루브릭을 점검한다.

## 제약

- 로그 파일을 **수정하지 않는다**. 읽기 전용이다.
- 채점은 루브릭 기준을 엄격하게 적용한다. 관대하게 주지 않는다.
- `.research/judge-variance.tsv`에 결과를 누적해, 시간이 지나며 채점기 신뢰도를 추적한다(`research-cycle-log.tsv`와 같은 철학).
- 이 커맨드는 **신뢰도만** 잰다. 타당도(편향) 보정은 별도로 사람이 골드 로그와 견주어 수행한다.
