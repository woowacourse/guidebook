# 페이지 업데이트 — 자라는 콘텐츠 일괄 갱신

> 뉴스레터처럼 외부에서 계속 새 항목이 발행되는 아카이브 페이지를, 라이브 소스와 대조(신선도 diff)해 **밀린 만큼만** 갱신하는 커맨드. 2026-07-03 뉴스레터 19→22호 갱신 파일럿에서 실측한 절차를 그대로 재연한다.

## 사용법

```
/페이지업데이트             # 등록된 전 소스의 신선도 리포트만 출력 (아무것도 수정하지 않음)
/페이지업데이트 뉴스레터     # 해당 소스만 갱신
/페이지업데이트 전체        # 밀린 소스 전부 순회 갱신
```

## 소스 레지스트리

**`.claude/page-update-sources.md`** — 소스별 라이브 URL, 항목 열거법, 갱신 대상 파일, 메커니즘 유형, 계수 의존 문구 위치, 주의사항이 전부 여기 있다. 커맨드 본문은 절차만 정의하고, 소스별 차이는 레지스트리가 흡수한다. **새 소스 추가 = 레지스트리에 항목 추가**(커맨드 수정 불필요).

## 실행 절차 (소스 1개 기준)

### 0. 신선도 diff — 항상 여기서 시작

- 레지스트리의 "항목 열거법"대로 라이브 소스에서 항목 목록(번호·날짜·제목·URL)을 추출한다.
- 아카이브 파일의 항목 목록과 대조해 밀린 항목을 계산한다.
- 리포트 형식: `소스 / 아카이브 N / 라이브 M / 밀림 K (밀린 항목: …)`
- **밀림 0이면 "밀림 0 — 변경 없음"을 보고하고 즉시 종료한다 (no-op).** 어떤 파일도 만들거나 수정하지 않는다.

### 1. raw 확보 — 발행본을 건드리기 전에

- 밀린 항목의 원문을 스크레이프해 `llm-wiki/raw/YYYY-MM-DD-<소스>-<번호>-<슬러그>.md`로 저장한다.
- frontmatter: `source_type / source / issue / published / captured / url / title`. 본문은 원문 보존(요약·재작성 금지 — 그건 wiki 단계의 일).
- ⚠️ raw는 불변이다. 기존 파일 수정은 protect-raw 훅이 차단한다. **새 파일 추가만** 한다. 방금 만든 미커밋 초안을 고쳐야 하면 `rm` 후 새로 쓴다.

### 2. 기계적 표면 — 판단이 필요 없는 부분 먼저

- 목록 표에 새 항목 행 추가, Callout의 발행 수·분석 범위 등 계수 갱신.
- 검증: 표 행 수 = 라이브 항목 수 (예: `grep -c '바로가기' <mdx>`).

### 3. 편집 표면 — 제안 후 반영

- 새 항목 원문(1단계 raw)을 읽고, 레지스트리의 "계수 의존 문구 위치"를 전부 점검한다.
- 기존 서사(흐름 절·관찰 표·추천 표·한 줄 요약)에 흡수되는지, 새 절이 필요한지 판정한다.
- **서사 변경은 초안을 사용자에게 제안하고 승인 후 반영한다.** 사용자가 "제안한 대로 진행" 등으로 일괄 위임한 경우에만 바로 반영한다.
- 검증: 옛 계수 grep 0건, `npm run lint:tone`·`npm run lint:codefence`에서 해당 파일 무위반. 본문은 합니다체.

### 4. 이중 기록·사이트 규약 마무리

- derived 미러 재생성 (Write/Edit가 아니라 스크립트 — 훅과 충돌하지 않는 공인 경로):
  ```bash
  node scripts/mdx-to-raw.mjs --input <발행 mdx> --output llm-wiki/raw/derived/<slug>.md --captured <오늘> --source-type derived-archive
  ```
- `content/updates.ts` 배열 맨 위에 항목 추가.
- `npm run build` 통과 확인 (llms.txt·llms-full.txt 자동 재생성).
- `llm-wiki/log.md` 맨 위에 `## [날짜] ingest | <raw 파일들>` 항목 append.
- 커밋 2건 분리: 발행 repo(콘텐츠 mdx + updates.ts), llm-wiki(raw + derived + log.md). 병행 세션의 WIP가 섞이지 않게 파일을 명시해서 `git add` 한다. `public/llms*.txt`는 생성물이므로 커밋에서 제외해도 된다(다음 빌드에서 재생성).

## 배치 모드 (`/페이지업데이트 전체`)

1. 전 소스 신선도 리포트를 먼저 출력한다.
2. 밀린 소스만 위 절차를 순회한다. **소스당 커밋을 분리**한다.
3. 마지막에 소스별 결과 요약 표를 남긴다: `소스 / 이전→현재 / 반영 표면 / 커밋`.

## 완료 보고 형식

```
✅ 뉴스레터: 19 → 22 (+3) — 표 3행, 계수 2곳, 서사 1절 신설, updates.ts, raw 3건, derived 재생성
⏭️ 테코톡: 밀림 0 — 변경 없음
```
