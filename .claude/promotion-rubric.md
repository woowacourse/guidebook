# 승격 루브릭 (Promotion Rubric)

> 이 파일은 autoresearch의 `prepare.py`에 해당한다.
> **절대 수정하지 않는다.** 평가 기준이 바뀌면 모든 이전 판정과 비교가 불가능해진다.
> 루브릭을 개선하고 싶으면 사람이 직접 이 파일을 수정한다.

## 목적

실험 로그(경험적 데이터)에서 상위 레이어(검증된 도구, 인사이트, 교육 모델)로
콘텐츠를 **승격(promote)**할 자격이 있는지 판단하는 기준.

로그 품질 루브릭(25점)과는 별개다.
- 로그 품질: "이 로그가 잘 작성되었는가?" (형식과 서술)
- 승격 적격성: "이 로그의 내용이 재사용 가능한 지식인가?" (내용과 패턴)

## 승격 대상 3단계

```
실험 로그 (26개)
    ↓ 승격 기준 통과
검증된 도구 (tools/)     — 복사해서 바로 쓸 수 있는 워크플로우/프롬프트/템플릿
인사이트 (insights/)     — 여러 로그에서 추출한 교차 패턴
교육 모델 (education-model/) — 원칙, 디자인 패턴, 커리큘럼에 반영
```

## 평가 차원 (4개, 각 1~5점, 총점 20점)

### P1. 반복 검증 (Replication)

같은 활동이 다른 기수/맥락에서 반복되었는가?

| 점수 | 기준 |
|------|------|
| 5 | 3개 기수 이상에서 반복, 매회 개선 기록 존재 |
| 4 | 2개 기수에서 반복, 비교 데이터 존재 |
| 3 | 1개 기수에서 실행했으나 변형 가능한 설계 원칙이 명확 |
| 2 | 1개 기수에서 1회 실행, 결과가 긍정적 |
| 1 | 1회 실행, 결과 불명확 또는 개선 여지가 큼 |

### P2. 추출 가능성 (Extractability)

로그에서 독립적인 도구/패턴/원칙을 뽑아낼 수 있는가?

| 점수 | 기준 |
|------|------|
| 5 | 명확한 단계별 워크플로우 + 템플릿/프롬프트가 로그 안에 이미 존재 |
| 4 | 워크플로우는 추출 가능하나 템플릿이 암묵적 (약간의 정리 필요) |
| 3 | 핵심 원칙은 식별 가능하나 구체적 도구로 만들려면 재구성 필요 |
| 2 | 좋은 아이디어가 있으나 일반화하기에는 맥락 의존적 |
| 1 | 특정 상황에만 적용 가능, 일반 패턴 추출 불가 |

### P3. 교차 연결 (Cross-Reference)

다른 로그, 인사이트, 교육 모델과 연결되는가?

| 점수 | 기준 |
|------|------|
| 5 | 3개 이상의 다른 로그와 패턴이 겹치며, 기존 교육 모델 원칙을 실증 |
| 4 | 2개 이상의 다른 로그와 관련 + 교육 모델 1개 섹션과 연결 가능 |
| 3 | 1개 다른 로그와 관련 또는 교육 모델과 간접 연결 |
| 2 | 독립적이나 기존 인사이트에 사례로 추가 가능 |
| 1 | 완전히 독립적, 다른 콘텐츠와 연결점 없음 |

### P4. 실행 영향력 (Impact)

이 패턴이 실제 교육에 미치는 영향이 얼마나 큰가?

| 점수 | 기준 |
|------|------|
| 5 | 교육 과정의 핵심 구조(커리큘럼/미션/평가)에 직접 영향 |
| 4 | 코치 운영 방식이나 크루 경험에 의미 있는 변화 |
| 3 | 특정 레벨/단계의 학습 효과에 기여 |
| 2 | 보조 활동으로 유용하나 핵심은 아님 |
| 1 | 실험적 시도로 의미는 있으나 실용적 영향 미미 |

## 승격 판정 기준

| 총점 범위 | 판정 | 행동 |
|-----------|------|------|
| 16~20 | **승격 가능** | 도구/인사이트/교육모델 중 적합한 곳에 추가 |
| 12~15 | **조건부 승격** | 특정 차원 보강 후 재평가, 또는 인사이트에만 사례로 추가 |
| 8~11 | **보류** | 추가 반복 실험 후 재평가 |
| 4~7 | **미승격** | 로그로 유지, 향후 반복 시 재평가 |

## 승격 대상 분류 기준

승격 가능 판정을 받으면 아래 기준으로 대상을 분류한다:

| 조건 | 승격 대상 | 예시 |
|------|-----------|------|
| P2 ≥ 4 (명확한 워크플로우/템플릿) | **검증된 도구** (tools/) | 프롬프트, 단계별 가이드, 템플릿 |
| P3 ≥ 4 (교차 패턴 식별) | **인사이트** (insights/) | 여러 로그의 공통 원칙 |
| P4 ≥ 4 + P1 ≥ 3 (영향력 + 반복 검증) | **교육 모델** (education-model/) | 디자인 패턴, 커리큘럼 원칙 |
| 복수 조건 충족 | **복수 대상에 동시 승격** | 도구 + 인사이트 동시 추가 |

## 평가 출력 형식

```
## 승격 평가: {로그 제목}

| 차원 | 점수 | 근거 (1문장) |
|------|------|-------------|
| P1. 반복 검증 | ?/5 | ... |
| P2. 추출 가능성 | ?/5 | ... |
| P3. 교차 연결 | ?/5 | ... |
| P4. 실행 영향력 | ?/5 | ... |
| **총점** | **?/20** | **판정: ?** |

### 승격 대상
- [ ] 도구 (P2={N}) — {구체적 도구명}
- [ ] 인사이트 (P3={N}) — {연결 패턴명}
- [ ] 교육 모델 (P4={N}, P1={N}) — {반영할 섹션}

### 승격을 위한 보강 사항
{조건부 승격인 경우 구체적 보강 방향}
```

## 교차 패턴 탐지 출력 형식

여러 로그를 교차 분석할 때 사용한다:

```
## 교차 패턴: {패턴명}

### 관련 로그
| 로그 | 카테고리 | 기여 요소 |
|------|----------|-----------|
| {로그1} | {카테고리} | {이 패턴에 기여하는 구체적 요소} |
| {로그2} | {카테고리} | {이 패턴에 기여하는 구체적 요소} |

### 패턴 요약
{2~3문장으로 패턴의 핵심}

### 승격 제안
- 대상: {도구/인사이트/교육모델}
- 제안 제목: {승격 시 사용할 제목}
- 근거: {왜 이 패턴이 승격할 가치가 있는지}
```
