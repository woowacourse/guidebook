# 인사이트 추출 — 교차 패턴 탐지

## 클러스터링 기준

각 로그에서 추출할 핵심 요소:
- **교육 설계 원칙** — 점진적 스캐폴딩, 거꾸로 학습 등
- **사용된 메커니즘** — POE 사이클, KPT 회고, 페어 활동 등
- **관찰된 효과** — 심리적 안전감, 메타인지, 전이 등

클러스터 유형:
1. **설계 패턴 클러스터** — 같은 설계 원칙을 사용한 로그들
2. **메커니즘 클러스터** — 같은 활동 구조를 사용한 로그들
3. **효과 클러스터** — 같은 교육 효과가 관찰된 로그들

## 패턴 강도 판정

- 3개+ 로그 겹침 → **강한 패턴** → 인사이트 문서 작성
- 2개 로그 겹침 → **약한 패턴** → 기록만, 추가 실험 대기
- 1개 로그만 → **독립 실험** → 건너뜀

## 인사이트 문서 작성 경로

`content/education/insights/{패턴명-slug}.mdx`

기존 파일이 있으면 덮어쓰지 않고 내용을 보강한다.
작성 후 `content/education/insights/_meta.ts`에 등록한다.

## 인사이트 문서 구조

```mdx
# {인사이트 제목}

<Callout>
**핵심 발견**: {한 문장으로 패턴의 핵심}
</Callout>

## 패턴 요약
{2~3문장으로 패턴이 무엇이고 왜 중요한지}

## 근거 실험
<CardGrid columns={2}>
  <Card title="{로그1 제목}" href="{로그1 링크}">
    {이 패턴에 기여하는 구체적 요소}
  </Card>
</CardGrid>

## 핵심 원칙
1. **{원칙 1}** — {설명}
2. **{원칙 2}** — {설명}
3. **{원칙 3}** — {설명}

## 적용 가이드
| 상황 | 적용 방법 | 주의점 |
|------|-----------|--------|

## 관련 교육 모델
- [{관련 원칙}](/education/{경로}) — {연결 설명}
```

## 커밋 형식

```
extract insight: "{인사이트 제목}" from {N} logs
```

## 제약

- 로그에 실제로 기록된 내용에서만 추출한다. 추측 금지.
- 약한 패턴을 강한 패턴으로 임의 승격 금지.
- 패턴 이름은 이 프로젝트의 언어 우선 (교육학 용어 지양).
