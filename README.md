# woowacourse-docs

우아한테크코스 공식 교육 가이드북. Nextra 4 + Next.js App Router 기반.

## 빠른 시작

```bash
npm install
npm run dev     # http://localhost:3000
```

## 콘텐츠 구조

```
content/
├── index.mdx                  홈 (RecentUpdates 타임라인 자동 렌더링)
├── updates.ts                 최근 업데이트 데이터 (단일 진실 원천)
└── education/
    ├── philosophy/            교육 철학 (근본 원칙, 이론적 기반)
    ├── design-patterns/       디자인 패턴 (검증된 교육 설계 패턴 카탈로그)
    ├── curriculum/            커리큘럼 (레벨별 설계 원칙)
    ├── insights/              인사이트 (실험 로그에서 추출한 교차 패턴)
    ├── tools/                 검증된 도구 (복사해서 바로 쓰는 워크플로우/프롬프트)
    └── logs/                  실험 로그 (매주 쌓이는 원재료)
```

## 연구 사이클 워크플로우

실험 로그를 원재료로 삼아, 검증된 패턴을 교육 모델로 끌어올리는 파이프라인입니다.

```
실험 로그 (logs/)
    ↓ 품질 평가·개선 (D1~D5, 25점)
    ↓ 승격 평가 (P1~P4, 20점)
    ├→ 검증된 도구 (tools/)           P2 ≥ 4
    ├→ 인사이트 (insights/)           P3 ≥ 4
    ├→ 디자인 패턴 (design-patterns/)  P4 ≥ 4 + P1 ≥ 3
    ├→ 커리큘럼 (curriculum/)          P4 ≥ 4 + P1 ≥ 3
    └→ 교육 철학 (philosophy/)         P4 ≥ 4 + P1 ≥ 4 (엄격)
```

### 상황별 커맨드 선택

> 어떤 커맨드를 써야 할지 모를 때는 여기서 내 상황을 먼저 찾으세요.

---

**방금 실험 로그를 작성했는데, 잘 쓴 건지 확인하고 싶다**

```
/review-log expedition
```

점수만 매기고 파일은 건드리지 않습니다. 어느 차원이 약한지 알려줍니다.

---

**점수를 보니 특정 로그 하나가 많이 약하다. 집중적으로 개선하고 싶다**

```
/improve-log expedition
```

가장 약한 차원부터 한 번에 하나씩 고쳐가며 최대 5번 반복합니다. 점수가 내려가면 자동으로 되돌립니다.

---

**로그가 여러 개 쌓였는데, 한꺼번에 전부 개선하고 싶다**

```
/improve-all
```

점수가 낮은 순서대로 하나씩 `/improve-log`를 실행합니다. 전체 평균이 B등급(16점)이 되거나 10개를 처리하면 멈춥니다.

---

**레벨1 로그가 5개 넘게 쌓였다. 공통 패턴을 뽑아 인사이트로 만들고 싶다**

```
/extract-insights 레벨1
```

3개 이상의 로그에서 겹치는 요소만 인사이트로 문서화합니다. 2개 이하는 "약한 패턴"으로 기록만 하고 추가 실험을 기다립니다.

---

**인사이트가 생겼는데, 교육 모델에 공식으로 반영하고 싶다**

```
/sync-model scan          # 먼저 뭐가 반영 대상인지 확인
/sync-model               # 실제 반영 실행 (한 사이클 최대 3건)
```

기존 교육 모델 내용은 건드리지 않고, 검증된 사례를 추가하는 방식으로 동기화합니다.

---

**지금 어떤 로그가 얼마나 준비됐는지 전체 현황을 먼저 파악하고 싶다**

```
/research-cycle dry-run
```

평가와 승격 후보 파악만 하고, 파일은 전혀 바꾸지 않습니다. 상황을 보고 판단한 뒤 전체 실행할지 결정하세요.

---

**전체 파이프라인을 한 번에 돌리고 싶다 (측정 → 개선 → 승격 → 동기화)**

```
/research-cycle
```

처음 쓰는 경우라면 `dry-run`으로 먼저 현황을 확인한 뒤 실행하는 것을 권장합니다.

---

**로그 몇 개를 추가했는데, 확인 없이 자동으로 처리하고 싶다**

```
/auto-sync
```

마지막 동기화 이후 새로 추가된 로그만 골라서 승격 평가 → 인사이트 추출 → 모델 동기화 → 단일 커밋까지 자동으로 처리합니다. 승격 점수 16점 미만인 로그는 자동 제외됩니다.

> 잘못됐다 싶으면 `git revert HEAD` 한 번으로 전체 원복할 수 있습니다.

---

### 커맨드 레퍼런스

| 커맨드 | 인자 | 파일 변경 | 한 줄 설명 |
|--------|------|-----------|------------|
| `/review-log` | `[slug]` | 없음 | 로그 품질 점수 측정 (읽기 전용) |
| `/improve-log` | `<slug>` 필수 | 로그 MDX | 특정 로그 차원별 반복 개선 |
| `/improve-all` | 없음 | 로그 MDX들 | 전체 로그 점수 낮은 순 순회 개선 |
| `/extract-insights` | `[카테고리]` | insights/ | 교차 패턴 탐지 → 인사이트 문서 생성 |
| `/sync-model` | `[slug\|scan]` | education-model/ | 인사이트 → 교육 모델 추가 반영 |
| `/research-cycle` | `[dry-run]` | 전체 | 전체 6단계 파이프라인 실행 |
| `/auto-sync` | 없음 | 자동 | 신규 로그 증분 처리 (비대화형) |

## 콘텐츠 추가 규칙

새 MDX 파일 추가 시 반드시 함께 처리:

1. **`_meta.ts`** — 해당 디렉토리에 새 항목 등록
2. **`content/updates.ts`** — 배열 맨 위에 추가 (랜딩 페이지 타임라인 자동 반영)
3. **`content/logs.ts`** — 실험 로그 추가 시에만 (`index.mdx`는 `<LogList />`가 자동 렌더링)

## 루브릭 (변경 금지)

평가 기준 파일은 사람만 수정한다. 기준이 바뀌면 모든 이전 점수와 비교 불가능해진다.

- `.claude/log-quality-rubric.md` — 로그 품질 (D1~D5, 25점)
- `.claude/promotion-rubric.md` — 승격 적격성 (P1~P4, 20점)
- `.claude/tool-promotion-rubric.md` — 도구 승격 기준
