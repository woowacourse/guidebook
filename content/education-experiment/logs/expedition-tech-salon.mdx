# 원정대 테크살롱: 공유회로 전이 설계하기

<Callout>
**대상**: 학습 공유회를 "발표"가 아닌 "전이"로 설계하려는 코치

**맥락**: 레벨 1 · 원정대 활동 2주 차, 첫 공유회를 앞둔 시점

**핵심 질문**: 원정대가 쌓은 지식을 다른 크루에게 실제로 전이시키는 공유회를 어떻게 설계할까?
</Callout>

## 배경과 문제

원정대 활동은 "송곳 같은 강점 만들기"를 목표로 2주간 팀별로 주제를 파고드는 활동입니다. 실행컨텍스트, 프로토타입 체인, 함수형 프로그래밍, TDD, SOLID — 5개 원정대가 각자의 주제를 탐구했습니다.

문제는 공유회였습니다. 기존 발표 방식에는 두 가지 한계가 있었습니다.

1. **발표자만 성장합니다.** 청중은 수동적으로 듣기만 하고, 실제로 지식이 전이되지 않습니다.
2. **발표 준비가 학습을 잡아먹습니다.** 크루들이 송곳(강점)을 깊이 파는 대신 발표 자료 제작에 시간을 쏟게 됩니다.

"공유는 발표가 아니라 전이다"라는 원칙을 세웠지만, 이를 실제 운영 구조로 만들어야 했습니다.

## 설계

### 핵심 원칙: 전이 중심 공유

"내가 잘했다"를 보여주는 시간이 아니라, 다른 크루가 내 방법을 바로 따라 할 수 있게 만드는 시간으로 설계했습니다. 공유 시 필요한 3가지를 명확히 했습니다.

1. 무엇을 시도했는가?
2. 어떤 결과가 나왔는가?
3. 다른 사람이 그대로 흡수할 수 있는 실습 활동은 무엇인가?

### 테크살롱 구조

"테크살롱"이라는 이름으로, 학술 컨퍼런스의 병렬 세션 형태를 차용했습니다.

| 설계 요소 | 내용 |
|-----------|------|
| 형식 | 여러 원정대가 동시에 세션을 열고, 크루가 원하는 세션을 선택 |
| 시간 | 세션당 50분 + 경험 공유 15분, 하루 4타임 운영 |
| 전수자 | 모든 원정대원이 전수자 — 1명 대표 발표 금지 |
| 공유 방식 | 앱으로 문제 풀기, 시각화, 게임, 함께 책 읽기, 토론 등 자유 |
| 오전/오후 분리 | 오전은 프론트엔드 크루 대상, 오후는 백엔드 크루와 교류 |

### 홍보물로 동기 부여

세션이 동시에 열리기 때문에 크루들의 선택을 받아야 합니다. 각 원정대가 홍보물을 제작하도록 했습니다. "예쁘게 만들 필요 없고, 오고 싶게 만들기만 하면 됩니다."

크루들은 미리캔버스, Gemini Canvas, GitHub Pages 등으로 홍보 페이지를 만들었습니다. 홍보물 제작 자체가 "이 주제의 핵심을 한마디로 전달하는" 연습이 되었습니다.

### 3일 전 설계 → 당일 실행

| 일시 | 활동 |
|------|------|
| 화요일 오전 | 공유회 설계 (v0.0.1) — 프로토타입 제작 후 팀 간 피드백 |
| 목요일 17시 | 홍보물 완성 및 크루 전체 공개 |
| 금요일 오전 | 테크살롱 본 행사 (프론트엔드 크루 대상) |
| 금요일 오후 | 타 교육 분야 크루와 교류 세션 |
| 금요일 마무리 | 팀별 회고 |

화요일에 설계 프로토타입을 만들고 다른 원정대와 피드백을 주고받은 뒤, 금요일에 본 행사를 진행하는 구조입니다. 3일간의 개선 루프를 의도적으로 넣었습니다.

## 결과

### 5개 원정대, 8개 세션

5개 원정대(실행컨텍스트, 함수형 프로그래밍, 프로토타입 체인, TDD, SOLID)가 하루 동안 총 8개 세션을 운영했습니다. 팀 규모에 따라 조를 나눠 같은 주제를 2회 진행한 팀도 있었습니다.

### 다양한 전수 방식의 등장

원정대별로 자유롭게 선택한 공유 방식이 흥미로웠습니다.

- **실행컨텍스트**: 도식화 문제, 객관식 퀴즈 등 다양한 형태로 문제를 출제
- **프로토타입 체인**: 슬라이드 + 테스트 크루를 활용한 사전 검증
- **TDD**: 찬반 토론 형식으로 TDD의 장단점을 함께 탐구
- **SOLID**: SRP → ISP → DIP로 점진적 리팩터링을 코드로 시연
- **함수형 프로그래밍**: 페어 프로그래밍 기반 실습 자료 제작

### 크루 회고에서 드러난 패턴

5개 팀의 회고에서 공통적으로 드러난 패턴이 있었습니다.

<Toggle title="긍정적 패턴">
- **전수 목표가 학습 동기를 높였습니다.** "발표회가 있어서 남한테 전수해야 되니 더 열심히 공부했다. 발표회 없었으면 미션 PR 피드백 반영부터 했을 것 같다." (실행컨텍스트 원정대)
- **다양한 전수 방식을 시도했습니다.** 도식화, 퀴즈, 토론, 페어 프로그래밍, 점진적 리팩터링 등 각 주제에 맞는 전달 방식을 고민한 흔적이 보였습니다.
- **열정적이고 능동적인 참여가 이루어졌습니다.** 여러 팀에서 자주 만나고, 실습 자료를 직접 제작하는 등 적극적인 활동이 있었습니다.
</Toggle>

<Toggle title="개선이 필요한 패턴">
- **"송곳"과 "발표" 사이의 괴리가 있었습니다.** 깊이 있는 학습(송곳 만들기)보다 발표 준비에 시간을 쏟게 되는 문제가 반복적으로 언급되었습니다. "발표 자체에만 집중하다 보니 보여주기식이 된 것 같다. 송곳의 끝이 뭉뚝했다." (실행컨텍스트 원정대)
- **2주는 짧았습니다.** 깊이 있는 탐구와 전수 준비를 동시에 하기에 기간이 부족했다는 피드백이 여러 팀에서 나왔습니다.
- **청중 참여 유도가 어려웠습니다.** 일방적 전달에서 벗어나려 했지만, 청중을 적극적으로 참여시키는 데까지는 도달하지 못한 팀이 있었습니다.
- **발표자가 청중보다 많은 세션이 있었습니다.** 소규모 정원 설정과 동시 세션 구조의 부작용이었습니다.
</Toggle>

## 교훈

### 1. "전이"라는 프레이밍은 효과적이었습니다

"발표가 아니라 전수여야 합니다"라는 한 줄의 룰이 공유 방식을 바꿨습니다. 크루들은 일방적 PPT 발표 대신 퀴즈, 토론, 페어 프로그래밍 등 참여형 방식을 자발적으로 설계했습니다.

### 2. 학습과 전수의 시간을 분리해야 합니다

2주라는 기간 안에 "깊이 파기"와 "전수 준비"를 동시에 하는 것은 무리였습니다. 크루들이 발표 준비에 매몰되면서 정작 송곳을 날카롭게 만드는 시간이 부족해졌습니다. 학습 기간과 전수 준비 기간을 명확히 분리하는 설계가 필요합니다.

### 3. 병렬 세션 구조는 선택권을 주지만 부작용도 있습니다

크루가 듣고 싶은 세션을 선택할 수 있다는 점은 동기 부여에 효과적이었습니다. 그러나 소규모 정원 제한으로 인해 발표자가 청중보다 많아지는 역전 현상이 발생했습니다. 세션 규모와 정원 설계를 더 세밀하게 조정해야 합니다.

### 4. 홍보물 제작은 예상 외의 학습 효과가 있었습니다

"오고 싶게 만들어야 한다"는 제약이 크루들에게 자기 주제의 핵심 가치를 한마디로 정리하게 만들었습니다. 미리캔버스, Gemini, GitHub Pages 등 다양한 도구를 활용한 것도 "매체를 가리지 않는" 원정대 콘셉트와 잘 맞았습니다.

### 5. 오후 교류 세션(백엔드 크루)은 토론 중심이 자연스럽습니다

오후에는 "준비해서 가르쳐야지"가 아니라 "토론하고, 질의하면서 서로 궁금한 것을 해소"하는 방향으로 안내했고, 이 프레이밍이 다른 분야 크루와의 교류에 더 적합했습니다.

## 다음 실험을 위한 제안

1. **학습-전수 기간 분리**: 최소 3주 학습 → 1주 전수 준비로 기간을 재설계합니다. 학습 기간 중에는 전수 형식을 고민하지 않도록 합니다.
2. **리허설 의무화**: 본 행사 전 최소 1회 리허설을 진행하고, 시간을 측정하여 조절합니다.
3. **소수 단위 활동 후 전체 공유**: 팀 내에서도 소수 단위(2~3명)로 먼저 공유하고, 이를 바탕으로 전체 공유회를 설계합니다.
4. **토론용 질문 사전 준비**: 각 세션에서 청중 참여를 유도할 토론 질문 1~2개를 필수로 준비합니다.
5. **정원 설계 재검토**: 발표자 수 대비 최소 청중 비율을 정하고, 세션 병합이나 시간대 조정으로 역전 현상을 방지합니다.
