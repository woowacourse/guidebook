# FE SSR 학습: 토론과 OX퀴즈로 "서버와 클라이언트의 평행세계" 체험하기

<Callout>
**대상**: SSR 같은 추상적 개념을 토론 기반으로 가르치려는 코치

**맥락**: 6기 FE 레벨4 SSR 미션 (2024)

**핵심 질문**: SSR 같은 "보이지 않는 실행 환경"의 차이를, 강의가 아닌 토론과 퀴즈로 발견하게 만들 수 있을까?
</Callout>

## 배경과 문제

SSR은 직관에 반하는 학습 주제다. 같은 JavaScript 코드가 서버와 클라이언트에서 다르게 동작하고, 하이드레이션처럼 눈에 보이지 않는 과정이 결과를 좌우한다. 강의로 듣고 미션 코드를 작성해도, "내가 실제로 무엇을 만들고 있는지" 모르는 상태로 통과하는 크루가 많았다.

## 설계

### 두 단계 활동

1. **토론 — JS의 평행세계, 서버와 클라이언트** ([Discussion #55](https://github.com/woowacourse/retrospective/discussions/55))
   - var 호이스팅 코드의 결괏값을 추론하기 (foo.js, bar.js의 변수 충돌)
   - 프리코스 자동차 경주 vs 레벨1 자동차 경주 저장소의 `package.json` 비교
   - Babel 트랜스파일링 직접 실행 후 원본 코드와 변환 결과 비교

2. **OX퀴즈 해설지 만들기** ([Discussion #56](https://github.com/woowacourse/retrospective/discussions/56))
   - SSR 본 미션 2단계 완성 기준의 4개 명제에 O/X로 답하고 **해설지를 작성**
   - 예: "초기 페이지 로드 시 웹 브라우저가 JS bundle 파일을 요청하지 않는다"
   - "하이드레이션 **과정**에서 첫 화면을 검증하지 않는다"처럼 미묘한 표현 차이를 의도적으로 배치

### 핵심 설계 원리

[비동기 퀴즈 해설지 만들기](/education-experiment/logs/async-quiz-explanation) 와 같은 **"해설지" 프레이밍**을 차용했다. "정답을 맞혀라"가 아닌 "왜 그런지 다른 사람에게 설명하라"는 과제다.

토론 활동(#55)이 **개념의 기초**를 다루고, OX퀴즈(#56)가 **본 미션 코드를 기준으로 한 검증**을 다루는 2단 구조다. 추상 → 자기 코드로 점진적으로 좁혀온다.

## 결과

- 단순 강의로는 드러나지 않던 "이해한 척"이 OX퀴즈 해설 과정에서 노출되었습니다.
- 특히 "하이드레이션 과정에서 vs 후" 같은 표현 차이가 깊이 있는 토론을 유발했습니다.
- Babel 직접 실행 활동이 "트랜스파일링이 무엇인가"를 코드로 체감하게 만들었습니다.

## 교훈

**잘 작동한 것**

- **토론 → 자기 코드 검증의 2단 구조**: 이론과 실전 사이의 간극을 좁히는 데 효과적이었습니다.
- **의도적인 모호성**: O/X 명제에서 표현을 의도적으로 모호하게 배치한 것이 토론을 유발했습니다. 명확한 정답이 있는 퀴즈보다 학습 효과가 컸습니다.
- **본 미션 2단계 기준 명시**: "사전 미션은 고려 X, 본 미션 2단계 완성 시점 기준" 이라는 명시적 제약이 토론의 혼선을 줄였습니다.

**개선이 필요한 것**

- **해설지 품질 편차**: 비동기 퀴즈 해설지와 동일한 한계 — 페어/팀에 따라 해설 깊이가 크게 달랐습니다.
- **다른 기수 반복 사례 부족**: 6기 1회만 운영되어 비동기 퀴즈처럼 3개 기수 누적 데이터가 없습니다. 차기 운영 시 해설지를 누적 자산으로 만들 가치가 있습니다.
