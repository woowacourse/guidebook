# 레벨0: 자기주도 학습 설계 실험 (안드로이드 8기)

<Callout>
**대상**: 입학 전 준비 과정을 설계하려는 코치

**맥락**: 레벨0 · 모바일 안드로이드 8기 (2026-01-26 ~ 2026-02-22, 4주)

**핵심 질문**: 입학 전 4주를 어떻게 구조화하면 크루 스스로 학습 루틴을 만들 수 있을까?
</Callout>

## 배경과 문제

기존 안드로이드 커리큘럼은 Kotlin 문법 습득에 집중하는 구조였습니다. 그러나 레벨1에서 반복적으로 관찰된 문제는 "문법을 아는 것"과 "왜 그 문법이 그렇게 설계됐는지 설명할 수 있는 것" 사이의 간극이었습니다.

특히 두 가지 패턴이 눈에 띄었습니다.

- 크루들이 Kotlin을 Java와 비교해서 설명하지 못하고, 단순히 외워서 사용하는 상태로 입학
- 학습 루틴이 없어 레벨1에서 급격하게 속도가 떨어지는 크루들이 반복적으로 발생

레벨0의 목표를 "Kotlin 완독"이 아니라 **자기주도 학습 역량 형성**으로 재정의하고, 이를 4주간의 구조화된 실험으로 설계했습니다.

## 설계

### 핵심 목표

지식을 빠르게 쌓는 시간이 아니라, **앞으로 이어질 긴 학습 여정을 완주하기 위한 자신만의 학습 루틴을 점검하고 만들어 가는 시간**으로 정의했습니다.

크루들에게 명시적으로 전달한 메시지는 이것이었습니다.

> '무엇을 공부했는가'보다 '어떻게 계획하고, 어떻게 돌아보았는가'에 의식적으로 집중해 보는 경험을 해보고자 합니다.

### 학습 구조

4주 전체를 3단계로 구성했습니다.

| 단계 | 주차 | 내용 |
|------|------|------|
| 계획 | 0주차 | 학습 계획서 작성 (최종 목표, 학습 자료, 주차별 계획, 회고 방식) |
| 실행 + 회고 | 1~4주차 | 매주 외부 플랫폼에 회고 작성 후 링크 제출 |
| 상호 관찰 | 2주차~ | 다른 크루 회고에 최소 1개 댓글 권장 |

### 학습 계획서 설계 의도

계획서 작성을 단순한 진도 계획이 아닌, 역량 중심으로 유도했습니다.

- **나쁜 목표 예시**: "Kotlin in Action 완독", "4주 동안 5장 읽기"
- **좋은 목표 예시**: "Java와 비교하며 Kotlin이 왜 null-safety를 언어 레벨에서 강제하는지 설명할 수 있다"

이 구분은 크루들이 "학습의 결과"를 역량으로 정의하도록 유도하는 장치였습니다.

### 학습 주제 가이드라인

Kotlin을 단순히 배우는 것이 아니라, Java와의 비교를 통해 언어 설계 철학을 이해하도록 아래 주제 목록을 제공했습니다.

- Kotlin 컴파일 과정과 JVM 실행 모델
- Java와 Kotlin의 타입 시스템 비교 (Null-safety, 타입 추론)
- 객체 지향 개념의 언어별 표현 방식 (final 기본값, open의 의미)
- 함수형 개념 도입이 만든 변화 (람다, 고차 함수, 컬렉션 API)
- 언어 기능과 개발자 경험의 관계 (보일러플레이트 감소, 실수 방지 장치)

## 교훈

**잘 작동한 것**

- **역량 중심 목표 설정 유도**: 계획서 작성 단계에서 "완독"이 아닌 "설명할 수 있다"로 목표를 프레이밍했을 때, 크루들의 회고 깊이가 달라졌습니다. 단순히 "챕터 몇 장 읽었다"가 아니라 "val과 var의 차이를 스택/힙 메모리 관점에서 설명할 수 있게 됐다"처럼 구체화되는 경향이 나타났습니다.

- **플랫폼 자유**: 회고 플랫폼을 지정하지 않은 결정이 좋았습니다. velog, 티스토리, Notion, GitHub 마크다운 등 각자에게 맞는 도구를 선택하면서 "회고를 어떻게 쓸까"보다 "무엇을 회고할까"에 집중할 수 있었습니다.

- **상호 관찰 구조**: 다른 크루의 학습 방식을 보는 것이 자신의 방향을 조정하는 데 도움이 됐다는 회고가 여러 크루에게서 나왔습니다. 강제가 아닌 권장으로 설계한 것이 참여 장벽을 낮춘 것으로 보입니다.

**개선이 필요한 것**

- **Java-Kotlin 비교의 깊이 편차**: 계획서에는 비교 학습을 목표로 쓴 크루가 많았으나, 실제 회고에서는 Kotlin 문법 정리에 머무른 경우가 많았습니다. Java 학습 자료(모던 자바 인 액션, 이펙티브 자바)를 병행 권장했지만, 실제로 Java를 깊게 학습한 크루는 소수였습니다.

- **계획 대비 실행 확인 부재**: 4주 계획을 스스로 세웠지만 중간에 점검하는 장치가 없었습니다. 4주차 회고에서 "계획했던 것을 다 못 했다"는 내용이 반복됐는데, 2주차 시점에 계획 재조정 세션을 넣었다면 더 현실적인 실행이 가능했을 것입니다.

- **학습 내용 공유 부재**: 회고는 "어떻게 공부했는가"를 주로 담았고, "무엇을 배웠는가"를 크루들끼리 공유하는 구조는 없었습니다. 학습 계획서처럼 한 주에 배운 핵심 개념을 짧게 정리해서 공유하는 구조를 추가하면 상호 학습 효과를 높일 수 있을 것입니다.

## 다음 실험을 위한 제안

레벨0의 구조가 **레벨1에서 학습 속도와 깊이에 실제로 영향을 미치는지** 추적하는 것이 다음 과제입니다.

구체적으로 추적하면 좋은 지표:
- 레벨0에서 바이트코드 실험을 한 크루와 이론 중심 학습을 한 크루의 레벨1 초반 코드 리뷰 피드백 패턴 비교
- 4주 계획을 완수한 크루와 부분 완수한 크루의 레벨1 회고 내용 비교
- "Java와 비교해서 설명할 수 있다"는 목표를 달성했다고 판단하는 크루의 기준이 실제로 유효한지 검증
