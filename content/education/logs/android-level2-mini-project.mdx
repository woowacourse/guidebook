# 안드로이드 레벨2 미니 프로젝트 수업 계획

<Callout>
**대상**: 안드로이드 레벨2 크루 17명 (3인 3팀 + 4인 2팀, 총 5팀)
**맥락**: 레벨2 하반기 4주간 진행되는 미니 프로젝트 수업. 제임스·디노 코치가 공동 운영. 화/금 2시간씩 총 8회차.
**핵심 질문**: 구현 완성도보다 문제 정의와 기술 선택의 근거를 어떻게 평가할 것인가?
</Callout>

## 맥락

레벨2 후반부에 크루들이 새로운 기술과 플랫폼을 직접 선택하고, 팀 단위로 MVP를 만들어보는 경험이 필요했다. 이전까지의 미션 중심 구조에서 벗어나 문제 정의 → 기술 선택 → 빠른 구현 → 검증의 흐름을 한 사이클 돌아보는 것이 목표였다.

"프로덕트 빌더로 성장한다"는 목표 아래, AI를 코드 생성 자동화 도구가 아닌 설계와 선택을 검토하는 협업 파트너로 활용하도록 의도했다.

## 시도한 것

**기간 및 구성**
- 기간: 2026년 5월 26일 ~ 6월 19일 (4주)
- 수업: 화/금 2시간, 총 8회차
- 팀: 17명을 5팀으로 구성 (3인 3팀 + 4인 2팀)
- 담당 코치: 제임스(James), 디노(Dino)

**주차별 흐름**

| 날짜 | 회차 | 활동 |
|------|------|------|
| 5/26(화) | 1회차 | 활동 소개 + 팀 구성 안내 |
| 5/27~28(수~목) | - | 팀별 자율 기획 작업 |
| 5/29(금) | 2회차 | 팀 소개 발표 + 플랫폼 탐색 발표 |
| 6/2(화) | 3회차 | 사용자 인터뷰 & 가설 검증 워크숍 |
| 6/5(금) | 4회차 | AI 수업 |
| 6/9(화) | 5회차 | 개발 중반 공유 |
| 6/12(금) | 6회차 | 팀 자율 작업 (개발 + 3주차 보고서) |
| 6/16(화) | 7회차 | 팀 자율 작업 (최종 발표 준비) |
| 6/19(금) | 8회차 | 최종 발표 + 팀별 회고 (14:00 시작) |

**발표 세션 구성 (2, 5, 8회차)**

팀당 18분. 오프닝 5분 → 팀별 공유 90분(18분 × 5팀) → 코치 종합 코멘트 25분.

**진행 공유 공통 포맷** (2회차·5회차)

각 팀이 아래 4가지를 중심으로 현재 진행 상황을 공유한다.
1. 정의한 문제를 풀기 위해 어떤 학습이 필요했는지
2. 실제로 학습이 어떻게 이루어졌는지
3. 학습한 내용이 문제를 해결할 수 있었는지
4. 앞으로 문제를 해결하기 위해 어떤 학습을 할 건지

**최종 발표(8회차) 발표 순서**

문제 정의 → 기술 선택 이유(안 쓴 선택지 포함) → 학습 과정 → MVP 결과 → 검증 결과 및 회고

**코치 운영 원칙**

- 구현의 정답을 제시하기보다, 기술 선택의 맥락과 한계를 짚어주는 역할
- "왜 이 기술인가? 안 쓴 선택지는 왜 뺐는가?"를 반복적으로 묻는 구조 유지
- AI 활용은 허용하되, 설계/구현/검증 과정에서 어떻게 활용했는지 근거를 남기도록 요구

## 반성

**잘 작동한 것**
- 4주 8회차 구조에서 발표 세션(2, 5, 8회차)을 균등하게 배치해 팀이 중간 점검 리듬을 가질 수 있도록 설계했다.
- 1주차 수~목 자율 기획 시간을 공식 일정에 포함시켜, 팀이 자율적으로 문제를 정의하고 기술을 선택할 공간을 확보했다.
- 공통 진행 공유 포맷(4가지 질문)을 고정해 팀 간 비교와 코치 피드백을 일관되게 운영할 수 있게 했다.
- 코치 피드백 기준을 "결과물보다 선택 과정과 판단 근거 중심"으로 명시해, 평가 기준에 대한 크루 혼란을 줄였다.

**개선이 필요한 것**
- 4회차 AI 수업 내용이 미정(후보만 제시)으로 남아 있어, 실제 수업 시작 전 확정이 필요하다.
- 팀별 회고를 레벨2 전반 회고와 분리해 운영하는 이유가 계획서에 명시되지 않았다 — 크루에게 별도 설명이 필요할 수 있다.
