# 설계: "이 문서는 어떻게 만들어지는가" 신뢰 페이지

- **날짜:** 2026-06-19
- **작성:** brainstorming 세션 (im1@woowahan.com)
- **상태:** 설계 확정, 구현 계획 대기

## 1. 목적과 배경

외부 독자는 이 문서의 **다듬어진 결과물**(철학·커리큘럼·검증된 패턴)만 봅니다. 그래서 "이건 그냥 멋진 말 아닌가? 위에서 내려온 선언이거나 AI가 뽑은 글 아닌가?"라는 의심이 *읽기 전에* 생깁니다. 이 문서의 콘텐츠는 실제로는 **아래에서 위로 승격**됩니다 — 실험 로그에서 귀납되고, 루브릭 점수와 게이트를 통과해야 올라가며, 새 로그가 쌓이면 언제든 수정됩니다.

이 페이지는 그 **제작 과정을 시각적으로 드러내** 신뢰도를 높이는 것이 목적입니다. 결과물이 어떻게 검증되며 만들어지는지를 보여줍니다.

### 신뢰의 세 기둥 (페이지 전체가 떠받칠 명제)
1. **귀납** — 주장은 위에서 떨어진 게 아니라 실험 로그에서 귀납된다.
2. **게이트** — 감이 아니라 루브릭 점수(품질 25점 / 승격 20점)와 임계값으로 승격된다.
3. **수정 가능** — 박제된 교리가 아니라 언제든 갱신되는 가설이다.

- **청중:** 외부 독자(회의적). **본문은 합니다체**(프로젝트 규약).

`content/education/tools/research-cycle-workflow.mdx`는 **코치가 기계를 돌리는 법**(슬래시 커맨드·dry-run, 내부용)입니다. 이 페이지는 **독자가 결과물을 믿는 법** — 슬래시 커맨드 없이 게이트·점수·숫자·수정가능성에만 집중하고, 둘은 서로 교차링크합니다. (이 페이지 → research-cycle-workflow를 "운영 세부가 궁금하면" 링크로.)

## 4. 비스포크 컴포넌트 `PromotionPipeline`

시각 투자 "핵심 1개". repo 관례(TypeScript + `.module.css` + `:global(.dark)` 다크모드)로 작성하고, Folio 디자인 시스템의 **autoresearch 점수카드 패턴**(차원 행 + 점수 막대 + 프로브 칩)을 이식합니다.

- **파일:** `components/PromotionPipeline.tsx` + `components/PromotionPipeline.module.css`
- **등록:** `mdx-components.tsx`, `components/index.ts`
- **`'use client'`** (상태 있는 인터랙션). 선례: `CurriculumTimeline.tsx`(스텝퍼 상태), `LogList.tsx`.

### 4.1 상단 — 파이프라인 흐름
3계층을 연결된 카드로 렌더링:

```
📝 실험 로그            ⟨게이트 A⟩          🛠️ 검증된 도구          ⟨게이트 B⟩          📐 커리큘럼
한 기수의 원본 기록   →  품질 루브릭 25점  →  💡 검증된 패턴       →  승격 루브릭 20점  →  🎯 철학
                        (B등급 16점 이상)                          (16점 이상 승격)
```

- 데스크톱: 가로 흐름(스테이지 카드 + 라벨 달린 게이트 커넥터). 모바일: 세로 스택.
- 게이트는 클릭 가능한 칩/버튼으로, 임계값을 표면에 노출.

### 4.2 게이트 클릭 → 루브릭 점수카드 펼침 (인터랙티브)
게이트를 클릭하면 해당 루브릭의 차원별 점수카드가 펼쳐집니다(아코디언). **실제 `.claude/*-rubric.md`와 1:1로 일치해야 합니다.**

**게이트 A — 품질 루브릭 (5차원 × 1~5점 = 25점)**
| 차원 | 이름 | 무엇을 보는가 |
|------|------|--------------|
| D1 | 구조 완성도 (Structure) | 필수 섹션을 갖췄는가 |
| D2 | 구체성 (Specificity) | 수치·인용·타임라인 등 구체 근거가 있는가 |
| D3 | 전이 가능성 (Transferability) | 다른 코치가 이 로그만으로 재현 가능한가 |
| D4 | 교훈의 양면성 (Balanced Lessons) | 성공·실패가 균형 있고 다음 행동으로 연결되는가 |
| D5 | 원본 자료 연결 (Source Linkage) | 디스커션·슬라이드·결과물 원본이 링크됐는가 |

등급: 21~25 A · 16~20 B · 11~15 C · 6~10 D · 5 F

**게이트 B — 승격 루브릭 (4차원 × 1~5점 = 20점)**
| 차원 | 이름 | 무엇을 보는가 |
|------|------|--------------|
| P1 | 반복 검증 (Replication) | 다른 기수/맥락에서 반복되었는가 |
| P2 | 추출 가능성 (Extractability) | 독립적 도구·패턴·원칙을 뽑아낼 수 있는가 |
| P3 | 교차 연결 (Cross-Reference) | 다른 로그·인사이트·모델과 연결되는가 |
| P4 | 실행 영향력 (Impact) | 실제 교육에 미치는 영향이 큰가 |

판정: 16~20 승격 가능 · 12~15 조건부 · 8~11 보류

- 데이터는 컴포넌트 안에 상수로 둠(주제가 컴포넌트 자신). "이 점수표는 실제 루브릭 파일과 동일합니다" 주석/캡션을 단다.
- 점수 막대 시각은 Folio `RubricRow` 차용 — 차원명 + 한 줄 설명 + 막대. (개별 로그의 실점수가 아니라 *기준*을 보여주는 게 목적이므로, 막대는 "만점 대비 차원 비중"이 아니라 각 차원의 정의를 드러내는 용도로 단순화.)

### 4.3 스타일
- 액센트: 사이트 블루 `#4285f4` (Folio `#3d6ff2`와 근사). 표면/텍스트: 기존 Notion 팔레트(`rgba(55,53,47,...)`) + `:global(.dark)`.
- 모션: 펼침 트랜지션은 `prefers-reduced-motion` 존중(선례: Mermaid/CSS).
- 반응형: 가로→세로 전환, 가로 오버플로 시 컨테이너 내부 스크롤.

[철학] 협업은 구조다
   ↑ 근거
