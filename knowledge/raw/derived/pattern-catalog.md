# 패턴 카탈로그

## 패턴 1. 단계적 제약 제거

> 학습자에게 처음부터 높은 자유도를 주면 방향을 잃고 학습 효과가 떨어진다.

**맥락** — 신규 학습자가 새로운 기술이나 개념을 처음 접할 때 발생하는 상황.

**해결책**

제약 조건을 점진적으로 완화하는 구체적 방법

**사례**

미션 레벨별 요구사항 변화 예시

**변형**

상황에 따른 패턴 변형

## 패턴 2. 반복적 재도전

> 한 번의 시도로는 깊은 이해에 도달하기 어렵다.

**맥락** — 학습자가 미션을 수행한 후 피드백을 받는 과정에서 발생하는 상황.

**해결책**

피드백 루프와 재시도 메커니즘

**사례**

코드 리뷰 기반 재도전 프로세스

**변형**

## 패턴 3. 동료 학습 촉진

> 개인 학습만으로는 다양한 관점과 문제 해결 능력을 기르기 어렵다.

**맥락** — 학습자 간 실력 차이가 있는 그룹에서의 협업 학습 상황.

**해결책**

페어 프로그래밍, 팀 프로젝트, 코드 리뷰 등

**사례**

**변형: 클린 랭귀지 기반 상호 멘토링**

크루들이 AI로 생성한 열린 질문 가이드를 활용해 서로의 고민을 탐색하는 방식입니다.
솔루션을 주는 대신 질문만으로 대화하므로, 실력 차이와 무관하게 누구나 멘토 역할을 수행할 수 있습니다.

→ 자세한 내용은 [AI 전략 > 클린 랭귀지 기반 상호 멘토링](/education/ai-strategy/usage-policy#사례-클린-랭귀지-기반-상호-멘토링) 참고

## 패턴 7. 자기 진단 프레임워크

> "좋은 X를 만들어라" 같은 추상어는 크루가 소화할 수 없다. 크루가 직접 돌릴 수 있는 진단 기준으로 번역해야 실행 가능해진다.

**맥락** — 학습 목표가 "성능을 높여라", "피드백을 잘 해라", "사용자 관점으로 다듬어라"처럼
추상적이어서 크루가 무엇을 어떻게 해야 할지 막막해하는 상황.

**해결책**

추상 가치를 **진단 차원 3~5개 + 점수 체계 + 자기 대상 적용**의 3박자로 분해한다.
크루가 자기 팀 산출물에 직접 템플릿을 적용해 리포트를 작성하게 하고, 다음 기수가 이 리포트를
입력 자료로 받아 누적 자산으로 만든다.

**사례**

- [FE 성능 리포트](/education/logs/fe-performance-report) — 측정→분석→개선 3단계 프레임워크를 5·6·7기에 걸쳐 진화
- [FE 접근성 리포트](/education/logs/fe-accessibility-report) — 성능 프레임워크를 접근성 도메인으로 이식, 6기 리포트를 7기의 누적 자산으로 명시
- [피드백 리팩터링](/education/logs/feedback-refactoring) — 5가지 진단 기준으로 기존 피드백을 "코드처럼" 진단

**변형**

성장 그래프처럼 **자기 자신이 진단 대상**이 되는 변형도 가능하다.
[나의 성장 그래프](/education/logs/growth-graph)는 기술/소프트스킬 성장 곡선과
감정 키워드를 결합한 시각적 자기 진단이다.

→ 근거 패턴: [인사이트 > 자기 진단 프레임워크](/education/insights/self-diagnostic-framework)

## 패턴 8. 점진적 스캐폴딩

> 한 번의 강의로 전달하면 증발하는 내용이 있다. 그런 주제는 3~5회의 시퀀스로 분산해 앞 회차가 뒤 회차의 토양이 되게 해야 한다.

**맥락** — 추상 개념이거나 실습·피드백·통합이 모두 필요한 주제를 "하루 특강"으로 전달했을 때
크루가 다음 주에 아무것도 기억하지 못하는 상황.

**해결책**

최종 목표 산출물을 정한 뒤 구성 요소를 역순으로 쪼개고, 각 회차의 산출물이 다음 회차의
입력이 되도록 순서를 맞춘다. 회차 사이에 1주 이상의 간격을 두고, 마지막 회차는 새 내용이
아니라 앞 회차들을 되짚는 회고 전용으로 예약한다.

**사례**

- [UX 리서치 3단계 훈련](/education/logs/ux-research-training) — 페어 글쓰기 → JTBD 인터뷰 설계 → UT 실전
- [FE 레벨2 16단계](/education/logs/fe-level2-16steps) — 적게 읽기/거꾸로 만들기/관점 전환 3가지 제약으로 16단계 설계
- [데모데이 회고의 점진적 설계](/education/logs/demo-day-retrospective) — 5회 연속 회고를 매회 다른 형식으로 설계해 성찰 깊이 점증

**변형**

제약을 매 회차마다 미세하게 조정하는 변형이 가장 효과적이다.
같은 주제를 단순 반복하면 지루해지고, 완전히 다른 주제면 연결이 끊긴다.

→ 근거 패턴: [인사이트 > 점진적 스캐폴딩](/education/insights/progressive-scaffolding)

## 패턴 9. 누적 학습 미션 설계

> 한 미션 저장소를 매년 새로 만드는 게 아니라, 변하지 않는 골격 위에 매년 새 학습 목표를 한 층씩 누적해 5~6년 단위로 누적 학습 자산을 만든다.

**맥락** — 같은 이름의 미션을 매년 운영하면서 학습 목표를 진화시켜야 하는 상황. 매년 저장소를 새로 만들면 데이터가 단절되고, 그대로 두면 학습 깊이가 정체된다.

**해결책**

영구 골격(form/state/component처럼 모든 기수에서 다뤄지는 핵심)과 누적 층(매년 한 단계씩 추상화돼 추가되는 새 목표)을 분리해 설계한다. 미션 재설계 결정은 5년치 PR 데이터로 카테고리×연도 매트릭스를 만들어 데이터 기반으로 한다.

**사례**

- [React 페이먼츠 미션 5년치 PR 555개 데이터 분석](/education/logs/react-payments-555prs-analysis) — form/state/component 4개 영구 골격 위에 2025 testing/error-handling, 2026 async/MSW가 누적된 패턴
- [자바 @MVC 미션](/education-experiment/repositories/java-mvc) — Controller 일관성 → Handler 추상화 → JsonView로 단계 누적
- [자바 로또 미션](/education-experiment/repositories/java-lotto) — 구현 1단계 → 리팩토링 2단계 구조 자체가 누적 학습 설계

**변형**

매년 폐지된 단계가 영구 폐지인지 일시 보류인지를 데이터로 재평가한다. 페이먼츠 3단계는 2024–2025 폐지 후 2026 부활. 폐지된 단계의 학습 목표가 다른 미션으로 이전 가능한지를 본문 데이터에서 검증하면 폐지 결정의 정확도가 올라간다.

→ 근거 패턴: [인사이트 > 미션은 누적 학습 모델이다](/education/insights/mission-learning-accumulation)
→ 분석 도구: [도구 > 미션 저장소 PR 데이터 분석 워크플로우](/education/tools/mission-repo-analysis-workflow)
